## Registry Table

**Five-class synthetic staging audit (2026-10-30):** the new `stance_context_wordchar_5class_synth_v1` candidate is exposed only at `POST /api/inference/stance/five-class-staging`. It uses reproducible synthetic training rows for Oppose, Mixed, and Unclear, all tagged as synthetic/training-only; no original dataset was overwritten. On the shared original-only 3x5 grouped folds, baseline accuracy/macro-F1/weighted-F1 was 0.6525/0.3048/0.6368; synthetic-augmented was 0.6483/0.2889/0.6276 (five-class macro includes zero-support Oppose and Mixed). The augmented model did not improve observed three-class macro-F1 (0.4814 vs 0.5080). Original evaluation support is zero for Oppose and Mixed, so this candidate is staging-only and not production-ready. Details, hashes, metrics and rollback are in `reports/stance_five_class_staging_v1/report.md` and the candidate manifest. Production artifact is unchanged.

**Active stance inference correction (2026-10-29):** `FinalStancePredictor` now emits only Support, Neutral and Unclear from the saved stance artifact. Sentiment no longer creates Oppose. The older heuristic registry row below describes historical behavior and is superseded by this correction. Current reference-pool metrics are development estimates; see `reports/stance_reference_model_comparison_v2/report.md`.

**Synthetic stance deployment audit (2026-10-29):** the latest like-for-like comparison is `reports/stance_candidate_shared_cv_v2/report.md`. On identical repeated grouped folds, the existing v1 candidate recipe averaged macro-F1 0.4677 ± 0.0410; the revised quality-gated v2 recipe averaged 0.4596 ± 0.0466 and lost to v1 on 10/15 folds. Keep v1 for traceability; do not create or promote v2. A versioned staging candidate is stored in `models/candidates/stance_wordchar_synthetic_v1/`; it is not wired into the API or UI. The active production artifact remains `data/stance_training_ai_working_labels/run_pool400_ai_v1_3class/pipeline_linsvm.joblib` (word-only LinearSVC, C=0.3). These results use a previously exposed reference pool and are not source-held-out validation.

1. **No Large Model Weights in Repository**: Pretrained model checkpoints (e.g. PyTorch `.bin`, `.safetensors`, model weights) are strictly stored outside the git repository to keep repository size lean and prevent bloat.
2. **Hugging Face Local Cache**:
   - Location: `C:\Users\MAYANK SWAROOP\.cache\huggingface\hub\models--sentence-transformers--all-MiniLM-L6-v2`
   - Loading method: `AutoTokenizer.from_pretrained(MODEL_ID)` and `AutoModel.from_pretrained(MODEL_ID)`.
   - Device: CPU (no GPU required for inference on MiniLM).
